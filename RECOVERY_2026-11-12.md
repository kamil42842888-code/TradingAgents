# Koral Equities recovery — 12 November 2026

This release restores the existing long-only paper system. Source recovery,
offline verification, Windows task registration, a zero-spend scheduler probe,
and paid-research activation are separate operations. No broker is connected.
Never use the old `INSTALL_DAILY_PAPER.cmd`: it combined installation with arming.

## Findings and source selection

The GitHub branch `feature/gbp-paper-equities-v1` was still at
`b5cb15b439947ba4fc9237c7ca0246dd507f6fdc`. All ten handoff package/evidence
hashes matched `SHA256_FILES.txt`. Both November 5 packages contain identical
daily trading modules. The manual package removes task-management and activation
helpers from the launchers; its source-only approach is the recovery baseline.
The October 30 packages supply the earlier bridge/controller integration tests.

Most local/repository differences are LF versus CRLF. The substantive local
runner difference omits GitHub's preclose earnings veto in the legacy research
path. This release preserves the stricter GitHub gate and imports the newer
daily modules, without overwriting unrelated local code or private configuration.
`tools/recovery/release_history.json` records accepted historical source hashes.

The incomplete installation was confirmed on Windows: Observer task disabled,
launcher/controller and several daily modules missing; controller task absent.
The original installer used encoded PowerShell, combined file replacement,
tests, task registration and `--arm`, and could leave a partly installed system.
The screenshots show a Bitdefender process-chain block and `CreateFile` access
denial with `bdhkm64.dll` on the stack. They establish a real failure, not its
exclusive cause or a false-positive verdict. This release does not change
antivirus settings, use exclusions or rename blocked files to bypass detection.

## Recovery changes

- Explicit manifests, known-revision checks, atomic writes, protected-file byte
  comparisons, durable source backups and an interrupted-update rollback record.
  Unknown edits, active exposure during source recovery and ambiguous locks halt.
- Runtime refuses an unfinished source update or incomplete source manifest.
- Standard, readable ScheduledTasks PowerShell commands. Registration leaves
  both production tasks disabled; no passwords or elevated task identity.
- Daily predeclared roster preserves held, pending and WATCHING symbols; a
  missing declaration never silently restores COST/JPM/WMT.
- Three preselected eligible companies may be attempted, even after SELL/HOLD.
  At most one conditional long plan is accepted per session. Existing position
  marking and exits occur before model research and survive model failures.
- Prepared mark transactions can finish after process termination using staged
  evidence and account bytes, without recomputing orders or calling a provider.
  Conflicting artifacts stop for reconciliation.
- Persistent attempt receipts and request reservations, no SDK retries, verified
  model output limits, and a budget overrun that remains stopped after restart.
- Operational summaries include incomplete data, errors, cash, equity, usage,
  decisions, plans, orders and positions. Historic account/audit evidence stays intact.

## Session and cost limitations

Dates and daylight saving follow `America/New_York`. The pinned calendar covers
2026–2027 and stops outside that coverage. Holidays and 13:00 early closes were
checked against the [NYSE calendar](https://www.nyse.com/trade/hours-calendars).
It is not an emergency-closure feed. Source incompleteness still blocks processing.

The legacy file name `preclose.json` means the earnings gate before the paper
controller's daily mark. It is collected **after exchange close**, not before
the closing auction. Normal windows: 08:45–09:25 earnings, 17:00–17:25 earnings,
market capture/processing from 17:40 NY. On published half-days the latter two
windows become 14:00–14:25 and 14:40. These retain the established data-delay
policy; the preopen earnings gate remains required for later simulated fills.

The computer must be powered, online and logged into the Windows account;
locking the screen is supported, signing out is not. Sleep/wake success depends
on Windows and hardware settings. A missed as-of observation cannot be recreated.
Flat gaps are explicitly recorded without invented intermediate marks or trades.
Gaps with exposure or conditional plans halt for reconciliation.

Default daily ceilings: three company attempts, 60 admitted model requests,
250,000 reserved token units, 2,048 output tokens/request, 100,000 prompt bytes.
UTF-8 prompt bytes plus framing headroom are a conservative admission estimate,
not provider tokenization. Missing usage retains reservations. These are **not
a guaranteed GBP/USD invoice cap**; provider billing and reporting remain external.
The live paid provider path and actual invoices require acceptance after activation.

Paper execution remains a daily-OHLC simulation, with later confirmations and
later-session fills, existing risk limits and stop/exit rules. It is not an
exchange-certified execution or performance record and does not establish ISA
eligibility of each security. No live broker integration is added.

## Windows procedure

Use a normal PowerShell window in the existing project. Keep antivirus enabled.
Extract the release ZIP into a separate review directory, for example
`D:\Koral_Recovery_2026-11-12`. Do not extract it over the project. If extraction
or any source write is blocked, retain the error and seek security review; do not
change exclusions, permissions, names or encoding to evade the block.

```powershell
$project = 'D:\Koral Equities' # Replace with the existing installation path.
$release = 'D:\Koral_Recovery_2026-11-12\Koral_Recovery'
$python = Join-Path $project '.venv\Scripts\python.exe'
Set-Location -LiteralPath $project
```

### 1. Read-only inspection

```powershell
& "$release\payload\Register_Koral_Tasks.ps1" -Mode Inspect -Project $project
& $python -B "$release\restore_sources.py" --project $project
```

Expect `KORAL_PREFLIGHT_STOPPED_AND_DISARMED; READ_ONLY`,
`SOURCE_RECOVERY_PREFLIGHT_OK`, `CHECK_ONLY; NO_CHANGES`.
Existing tasks must be disabled, Koral Python processes stopped normally and
the account flat. Do not delete an unknown account lock. The manifest also
verifies the unchanged application prerequisites.

### 2. Source installation only

```powershell
& $python -B "$release\restore_sources.py" --project $project --apply --tasks-disabled
```

Expect `SOURCE_RECOVERY_COMPLETE_NOT_ARMED`, a backup path, and
`ACCOUNT_AND_ENV_AND_OPERATION_CONFIG_BYTES_UNCHANGED`.
The account, `.env`, operation configuration and task definitions are untouched.
Known files already at the release version are not replaced.

If interrupted, keep tasks disabled, inspect the recorded failure, then:

```powershell
& $python -B "$release\restore_sources.py" --project $project --rollback --tasks-disabled
```

Expect `SOURCE_ROLLBACK_COMPLETED`. Changed protected data or externally changed
source files stop rollback for review; the tool never rolls back the portfolio.
Backups remain in `_Koral_Equities_Source_Backups`.

### 3. Dependency verification and isolated tests

```powershell
& $python -B '.\Verify_Koral_Recovery.py'
& $python -B '.\Verify_Koral_Recovery.py' --tests
& $python -B '.\Verify_Koral_Recovery.py' --account-check
```

Expect `DEPENDENCIES_AND_SOURCE_HASHES_OK`, `OFFLINE_TESTS_PASSED`, then
`EXISTING_ACCOUNT_AUDIT_AND_SOURCES_VERIFIED`. No dependency changes are installed.
Tests use a separate temporary home, mock providers and blocked network fixtures.
The read-only account check separately verifies the original audit chain and
bound evidence; compare its account hash with the pre-install value.

### 4. Register disabled tasks and test a zero-spend scheduled launch

```powershell
.\Register_Koral_Tasks.ps1 -Mode Register
.\Register_Koral_Tasks.ps1 -Mode Probe
```

Expect `KORAL_TASKS_REGISTERED_DISABLED` and
`WINDOWS_SCHEDULER_PROBE_PASSED; production tasks remain DISABLED`.
The probe uses a temporary, demand-started task and verifies its matching nonce,
completion result and installed manifest hash. It imports the runtime but does
not collect market data, call models or write the account. Existing task XML is
backed up; unknown task identities are preserved. Task APIs follow Microsoft's
[ScheduledTasks documentation](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset).

### 5. Explicit final activation — choose a billing route

For ChatGPT subscription-only operation, first turn off **Allow other apps to
use credits after reaching your usage limit** in ChatGPT Settings > Usage.
Keep that setting off while the schedule is active. Then use:

```powershell
.\Register_Koral_Tasks.ps1 -Mode Activate -ChatGPTPlanOnly -ConfirmPaidCreditsDisabled
```

This records the operator's confirmation, binds it to the saved ChatGPT sign-in,
and refuses either model tier using an API-key provider or another endpoint.
The program cannot remotely inspect that billing setting; the confirmation is
not a claim of an independently verified invoice cap. Included usage is shared
with the account's other ChatGPT/Codex work; exhaustion can stop research.

OpenAI's [subscription interface](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)
does not accept `max_output_tokens`. In this mode the 2,048 setting is an
admission allowance, not a server output cap. Every request reserves all remaining
daily units until completed inference reports usage. A missing terminal event,
unknown usage, interrupted request, or observed overrun stops further research
for that session, including after restart. One response can exceed the estimate;
the daily token admission budget is not a hard server-generation ceiling.
The 60-request and three-company limits still apply. Portfolio marking and exits
are independent of research failures. No automatic API fallback is permitted.

For a separately authorised API-billed route, use the alternative below.

Run only after reviewing the installed results and explicitly accepting paid
research. Recovery and registration never run this step automatically.

```powershell
.\Register_Koral_Tasks.ps1 -Mode Activate -AcceptModelCharges
```

Expect `DAILY_PAPER_SCHEDULE_ARMED` and `KORAL_PAPER_SCHEDULE_ACTIVE`.
Activation requires test and scheduler receipts matching the installed manifest.
It freezes the first eligible future roster without changing account flags.
Activation at/after 08:45 NY selects the next scheduled session; it does not
repeat any previously recorded analysis.

To stop future scheduled work normally:

```powershell
.\Register_Koral_Tasks.ps1 -Mode Disarm
```

This disables the two owned tasks and disarms the controller. It does not kill
an in-flight request, reset the account or delete evidence/locks.

## Acceptance checklist

- Source hashes and installed tests pass; pre/post ledger SHA-256 agrees, with
  the original account values, audit history and last-session date preserved.
- Both tasks have exact owned actions, five-minute triggers, Interactive logon,
  IgnoreNew instances, WakeToRun and explicit working directory.
- Zero-spend Windows scheduled probe receipt matches the current source manifest.
- After separately approved activation, Observer archives the declared ticker
  set for both earnings windows, then market OHLC, SPY and GBP conversion.
- A genuine future session produces a summary and at most three attempt receipts;
  repeated polls leave attempt count, orders and session events unchanged.
- A BUY, if independently justified, creates only a WATCHING plan first; valid
  future closes and a later simulated opening are required. SELL/HOLD/no-trade
  and rejected allocations remain legitimate results.
- Missing or changed evidence is visible in status; exposure gaps halt. Confirm
  actual provider usage and daily-OHLC limitations before judging performance.

Operational files are under `%USERPROFILE%\.tradingagents\paper_operations\daily_v1`:
`heartbeat.json`, `summaries`, `rosters` and `logs`. Original evidence remains under
`observations\koral_v3`; the existing account remains under `paper\v3_autopilot`.
Code tests and a launch probe do not prove a genuine unattended trading session.
