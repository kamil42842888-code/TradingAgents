# AI scan data warnings — 20 November 2026

The reported messages establish missing inputs, not the final outcome of the
scan. A completed report can still have unavailable company news, Reddit and
macro data. Inspect the saved run's completion status and its source disclosures
before describing the scan as complete and fully supported.

## Findings

| Message | Verified interpretation |
|---|---|
| GBPUSD open/close accepted despite inconsistent vendor high/low | The paper price loader accepts valid FX open/close and preserves the vendor's values. It warns about the daily range; it does not repair or clamp prices. |
| Yahoo `YFDataException` in `get_news` | The request failed. The wrapper exposes the exception type, so this log alone does not establish its underlying cause. |
| `trying next vendor` | The previous router logged this even for the only or last configured vendor. The default company-news chain contains only `yfinance`. |
| Reddit RSS HTTP 404 | The fetcher reports unavailable data, not an absence of discussion. Reddit announced retirement of RSS on 13 November 2026. |
| FRED key missing | Optional macro enrichment is unavailable to the process. Repeated tool calls can repeat this warning without representing new configuration faults. |

The router returns `DATA_UNAVAILABLE` after exhausting typed unavailable news
providers and when optional FRED enrichment cannot be served. These paths do
not establish that the overall run stopped. The sentiment analyst also calls
the model with explicit unavailable-source placeholders and asks it to disclose
reduced confidence. The supplied excerpt does not show StockTwits' result or
the final report.

## Corrections in this followup

1. Log a next configured vendor only when one remains. Otherwise report that
   the configured vendor chain is exhausted. Provider selection, return values
   and exception propagation are unchanged.
2. Require the supported Atom feed root for Reddit responses. A well-formed XML
   error page must produce unavailable data, not a false claim of no discussion.
   HTTP 404 remains unavailable and is not retried.

These corrections improve diagnostic accuracy. They do not restore Reddit RSS,
verify Yahoo access on Windows, add credentials, or prove scan completion.

## Efficient Windows followup

Use the interpreter and configuration of the scan that produced the warnings.
Do not assume the recovery directory is the active installation solely because
it was the documented destination.

1. Record the active project path, interpreter, `yfinance` and `curl_cffi`
   versions, and the effective company-news vendor chain. Inspect the existing
   run's final status and report before launching more model work.
2. Check Yahoo with a bounded provider-only request in that environment. Keep
   exception type and a sanitized cause; omit cookies, tokens and credentials.
   An upstream report describes this exact symptom with `yfinance 1.7.0` and a
   successful same-machine comparison with `1.8.0`. It is a diagnostic lead,
   not proof of this installation's cause. Test a needed dependency change in
   an isolated environment and reconcile the exact dependency pins before
   using it in the restored environment.
3. Treat public Reddit RSS as unavailable following retirement. Do not substitute
   missing discussion with neutral sentiment or add speculative endpoint retries.
   Replacing the provider requires a supported, authorized source and a separate
   change; the supported moderation replacements in Reddit's announcement are
   not a general replacement for these market-discussion feeds.
4. If macro enrichment is wanted, obtain the user's own FRED key through the
   official account flow and configure `FRED_API_KEY` privately for the identity
   and process running the scan. Verify presence without printing its value and
   validate one FRED request. If no key is available, retain explicit missing
   macro evidence. A new shell's environment does not prove an already-running
   dashboard or scheduled task has inherited the key.
5. Verify a single bounded scan only after source checks are understood. Record
   which inputs were available, which were absent, and whether a final report
   was saved. Model access and billing restrictions remain separate checks.

Do not install this change by editing hash-pinned runtime files in place. The
normal source-update builder includes both changed modules and their tests,
recognizes the previous reviewed files, and preserves protected prerequisites.
Build this dated followup with `--release 2026-11-20`. Windows placement, native
validation and scheduler activation require their own evidence; this followup
does not establish any of them.

## Validation scope

The focused Linux verification passed 156 tests and 14 subtests, covering vendor
routing/errors, Reddit parsing, news date filtering, FRED, FX quotes and source
recovery. Ruff and whitespace checks passed. The dated package built with 47
payload files and 102 protected prerequisites. This is not a Windows execution
or a live-provider acceptance result.

The regression tests use mocked provider responses, with no live provider or
model calls. Coverage distinguishes sole/first/last vendor failures, preserves
configured fallback behavior, rejects unsupported XML, accepts a valid empty
Atom feed, and checks that HTTP 404 does not trigger retries.
